# 커밋 컨벤션

## 기본 형식

```
<type>(<scope>): <subject> (<기능ID>)

<body> (선택)
```

예시:

```
feat(be): 지식 문서 조회 API 추가 (F-001)

문서 목록 페이지네이션 및 카테고리 필터링 로직 포함
```

## Type

| Type | 용도 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `design` | UI/디자인 변경 (색상, 레이아웃, 애니메이션 등) |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `style` | 포매팅, 세미콜론 등 로직 무관 변경 |
| `test` | 테스트 코드 추가/수정 |
| `docs` | 문서 수정 |
| `chore` | 빌드 설정, 패키지 매니저, CI 등 |

### 헷갈리는 type 구분

**`design` vs `style`** — 렌더링 결과(화면)가 달라지면 `design`, 안 달라지면 `style`.

- `design(fe): 온보딩 진행 상태 바 색상 변경 (F-002)` — 화면이 바뀜
- `style(fe): 컴포넌트 파일 포매팅 정리` — 화면 그대로, 코드만 정리

**`refactor` vs `style`** — 코드 구조/로직이 바뀌면 `refactor`, 텍스트 표현만 바뀌면 `style`.

- 판별법: 포매터(Prettier, Spotless)가 자동으로 할 수 있는 변경이면 `style`, 사람이 판단해서 코드를 재작성했으면 `refactor`
- `refactor(be): 문서 조회 중복 로직 메서드 추출 (F-001)` — 구조가 바뀜
- `style(be): import 순서 정렬` — 포매터 수준의 변경

한눈에 정리:

| type | 동작 | 코드 구조 | 텍스트 |
|------|------|----------|--------|
| `feat` / `fix` | 바뀜 | 바뀜 | 바뀜 |
| `refactor` | 그대로 | **바뀜** | 바뀜 |
| `style` | 그대로 | 그대로 | **바뀜** |

이 구분이 중요한 이유: 버그 원인을 추적할 때 `style` 커밋은 후보에서 제외할 수 있다. `refactor`를 `style`로 잘못 달면 이 필터링이 깨진다.

## Scope

| Scope | 대상 |
|-------|------|
| `be` | `backend/` 하위 변경 |
| `fe` | `frontend/` 하위 변경 |
| (생략) | `docs/`, 루트 설정 등 코드 외 변경 |

- 백엔드와 프론트를 한 커밋에 섞지 않는다. 부득이하게 섞이면 `feat(be,fe):` 로 표기한다.

## 기능ID

- 기능정의서의 기능ID(`F-001` 형식)를 subject 끝에 괄호로 붙인다
- 기능별 커밋 추적용: `git log --oneline | grep F-001` 으로 해당 기능 커밋을 모두 조회 가능
- 특정 기능에 속하지 않는 커밋(설정, 문서, 공통 리팩토링 등)은 생략 가능
- 기능정의서 확정 전 커밋은 ID 없이 작성해도 된다

## Subject 규칙

- 50자 이내
- 한국어로 작성, 명령형/서술형 종결 ("~추가", "~수정")
- 마침표 없이 끝낸다
- 무엇을 했는지가 제목만 보고 파악되어야 한다

**좋은 예:**
- `feat(be): 지식 문서 목록 조회 API 추가 (F-001)`
- `feat(fe): 온보딩 수료 처리 버튼 추가 (F-002)`
- `fix(be): 문서 검색 시 삭제된 문서 포함되는 버그 수정 (F-001)`
- `design(fe): 관리자 대시보드 레이아웃 변경 (F-004)`
- `chore: TeamCity CI 빌드 설정 추가` (기능ID 없는 커밋)

**나쁜 예:**
- `수정` (무엇을?)
- `feat: 작업` (의미 없음)
- `feat(be)/F-001: 문서 추가` (type/scope 형식 깨짐 — ID는 끝에 괄호로)
- `feat(be): 컨트롤러 수정하고 서비스 고치고 테스트 추가` (커밋 쪼개기)

## Body 규칙 (선택)

- 제목만으로 부족할 때 **왜** 변경했는지 위주로 작성
- 제목과 본문 사이 빈 줄 하나

## 커밋 단위

- 하나의 커밋 = 하나의 논리적 변경
- "오늘 작업 전부" 같은 몰아넣기 커밋 금지
- 커밋이 너무 커지면 쪼갤 수 없는지 먼저 고민한다
