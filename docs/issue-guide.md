# 이슈 가이드

## 이슈 생성 규칙

- 모든 작업은 이슈에서 시작한다 (이슈 → 브랜치 → PR)
- 제목은 위 형식에 맞게 작성: `[BE] [기능] F-002 - 바코드 조회 API 구현`
- 담당자(Assignee)를 반드시 지정한다
- 이슈 본문은 `.github/ISSUE_TEMPLATE/` 의 템플릿을 따른다

## 이슈 제목 형식

**기능 관련 이슈:**
```
[분야] [분류] 기능ID - 작업 내용
```
- `[분야]`: `[BE]` (백엔드) 또는 `[FE]` (프론트엔드)
- `[분류]`: `[기능]`, `[버그]`, `[리팩터링]` 중 하나
- `기능ID`: 기능 정의서의 ID (예: `F-001`)
- `작업 내용`: 구현할 기능/수정할 버그를 명확히 요약

예시:
- `[BE] [기능] F-001 - 회원 가입 API 구현`
- `[FE] [버그] F-003 - 상품 목록 페이지네이션 오류 수정`
- `[BE] [리팩터링] F-012 - 상품 조회 로직 최적화`

**비기능 이슈 (공통 작업):**
```
[분야] [분류] 작업 내용
```
- `[분야]`: 담당 파트를 `[BE]`, `[FE]`, `[공통]` 중 선택
- `[분류]`: `[문서]`, `[환경]`, `[리팩터링]` 중 하나

예시:
- `[공통] [문서] API 명세 업데이트`
- `[BE] [환경] 로컬 DB 설정 스크립트 작성`
- `[FE] [리팩터링] 컴포넌트 폴더 구조 정리`

**비기능 이슈 중 특정 기능과 관련된 경우:**
```
[분야] [분류] 기능ID - 작업 내용
```
- 해당 기능의 기능ID를 포함하여 연관성 표시

예시:
- `[BE] [문서] F-022 - 결제 API 스펙 업데이트`
- `[FE] [환경] F-031 - 장바구니 기능 테스트 설정`

## 라벨 체계

| 라벨 | 용도 |
|------|------|
| `enhancement` | 기능 추가/개선 |
| `bug` | 버그 |
| `documentation` | 문서 |
| `environment` | 개발 환경, 빌드, 배포 관련 |
| `refactoring` | 코드 리팩터링 |
| `urgent` | 우선 처리 필요 |

- 제목의 분류에 맞는 라벨 사용
- 필요에 따라 `environment`, `urgent` 조합 가능 (버그 중 급한 것은 `bug`+`urgent` 등)
